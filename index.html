    Optimize nodes: parameters & impact

    The optimizer refits every path with fewer Bézier segments. Corners are always kept, and a path is only replaced when the result has fewer segments than the original, so a run never makes a path heavier. Arcs (A commands) are left untouched.

    Tolerance0.01–1.00% · default 0.10%

    The maximum distance the new curve may drift from the original outline, measured as a percentage of the canvas (viewBox) diagonal. Shapes with a scale transform are compensated automatically. Example: on a 1000 × 1000 canvas, 0.10% allows about 1.4 units of deviation.

    • Higher fewer nodes and a smaller file, but fine details, tiny bumps and thin features can flatten or disappear.
    • Lower nearly lossless, but fewer nodes are removed.
    Corner angle5–90° · default 30°

    A join that turns sharper than this angle is treated as a corner and always stays a node. Gentler joins are treated as smooth and may be merged into a single curve.

    • Higher more joins count as smooth, so polygons with many small facets become round curves and node count drops.
    • Lower slight kinks and chamfers survive, with more nodes. Use 10–15° for technical drawings, 45° or more for noisy auto-traced shapes.
    Keep extrema nodeson by default

    Places and keeps nodes at the horizontal and vertical extreme points of each curve (leftmost, rightmost, topmost, bottommost).

    • On handles stay horizontal or vertical there, curves fit more accurately and are easier to edit, and the shape’s true bounds are preserved.
    • Off allows longer curves between nodes. It can save a few nodes, but extremes may shift slightly.
    Keep inflection pointson by default

    Keeps a node where a curve switches its bend direction, such as the middle of an S-curve.

    • On S-shaped and wavy outlines keep their character, even at higher tolerance.
    • Off one curve may span the whole S bend. This saves nodes, but subtle waves can flatten.
    Simplify polylineson by default

    Thins out the points of <polyline> and <polygon> elements (Douglas–Peucker). They stay polylines; they are not converted to curves. <path> elements are not affected by this option.

    • On far fewer points on dense polylines.
    • Risk at high tolerance, corners smaller than the tolerance are cut off.
    Purify while optimizingon by default

    Removes comments, metadata and editor-specific elements (CorelDRAW, Illustrator, Inkscape and similar), lock and protection attributes, unused namespace declarations and empty <defs>. Groups that hold only one element are unwrapped, and their transform and inheritable styles move onto that element. The XML version and UTF-8 declaration are kept.

    • On a cleaner, smaller file with simpler structure.
    • Note layer names and unreferenced group IDs are dropped, so scripts or CSS that target them will stop matching. Groups referenced by use, url(#…) or CSS are never unwrapped.
    Decimal precision1–6 · default 3

    How many decimals are written for every coordinate in the optimized path data.

    • Fewer decimals shorter numbers and a smaller file. 1–2 decimals suit canvases of about 500 units or more.
    • Risk on small canvases (for example 24 × 24 icons), 1–2 decimals can visibly shift points. Keep 3 or more there.
